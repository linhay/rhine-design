# 莱茵设计 · 字体与文字规范 V1.3

2026-10-22。适用于使用莱茵设计的中文界面与中英文混排。变量定义在 [tokens.css](./tokens.css)，样式与 React 入口分别为 [typography.css](./typography.css)、[Typography.tsx](./Typography.tsx)。归属与接入见[套件入口](../README.md)。

## 字体与字重

- 界面：`-apple-system, BlinkMacSystemFont, 'Segoe UI', 'PingFang SC', 'Microsoft YaHei', 'Noto Sans CJK SC', sans-serif`。使用平台已有字体；未安装的字体按顺序回退，不下载字体文件。
- 代码与路径：`ui-monospace, SFMono-Regular, Menlo, Consolas, 'Liberation Mono', monospace`。模型 ID、路径、协议值用等宽；普通英文说明仍用界面字体。
- 常规400、标签500、标题600。避免轻字重、小字号粗细堆叠、650等中间字重和浏览器伪斜体；不全局使用700。Logo字标遵循品牌组件，不作为业务文字模板。
- 系统字体选择与语义字号层级参考 [Fluent Typography](https://fluent2.microsoft.design/typography)；具体尺寸和中文规则是本项目的设计决策，不复制其全部字号。
- `.rhine-theme` 禁止字体伪造；不同系统的字面宽度可能不同，不能用固定字符串宽度或固定容器高度实现布局。

## 文字层级

| Text variant | 字号 / 行高 | 字重 | 使用场景 |
| --- | --- | --- | --- |
| title | 30 / 38px | 600 | 登录或独立引导标题；紧凑工作区不重复放大标题 |
| section | 18 / 26px | 600 | 主要内容分区 |
| heading | 16 / 24px | 600 | 卡片身份、次级分组 |
| body | 14 / 22px | 400 | 正文、解释 |
| label | 14 / 22px | 500 | 表单标签与主要操作 |
| caption | 12 / 18px | 400 | 时间、来源、辅助说明 |
| overline | 12 / 18px | 500 | 少量分类标签；中文正常字距；`lang="en"` 时0.08em字距 |
| metric | 26 / 32px | 600 | 关键数值，等宽数字；窄窗组合可切换20 / 26px变量 |
| code | 12 / 20px | 400 | 路径、模型标识、技术值 |

不低于12px承载业务信息。展台的宣传型大标题不属于 App 正文尺度。字号不是HTML语义：Text默认渲染p，按结构显式选择 `as="h1" / "h2" / "h3"`；不要为了字号跳过标题级别。段落间距由布局负责，不用空行字符撑开。

```tsx
<Text as="h2" variant="section">今日用量</Text>
<Text variant="body">选择 OAuth 账号后开启自动同步。</Text>
<Text variant="caption" tone="muted">最近检查 14:32 · 上海</Text>
<Text as="span" variant="metric" numeric>1,280</Text>
<Text as="code" variant="code">gpt-6.1-sol</Text>
```

## 混排、数字与单位

- 中文正文不增加字距，不做两端强制分散；段落左对齐，长说明建议不超过60ch。居中仅用于简短空态与品牌展示。
- 中文与独立英文/数字之间保留一个半角空格，例如「已完成 128 次请求」「使用 API-Key」。中文叙述用中文标点；模型 ID、路径、代码保持原样，不插入空格或改变大小写。
- 数量、时间、费用使用 `tabular-nums lining-nums`，数字表列右对齐，文本列左对齐。等宽数字不等于必须改用等宽字体。
- 产品统一显示：整数 `1,280`；概览缩写 `1.4M`；额度 `76%`；时长 `2.4 s`；日期 `2026-10-22`；时间 `14:32`。跨日或跨时区信息补全日期与「上海 / UTC+8」。业务确认的货币用明确币种或货币符号，不凭空换算。
- 同一指标的小数位固定：费用概览示例 `$5.44`、明细示例 `$0.0384`；展示格式由业务层按精度约定决定，Text不舍入数据。概览缩写应能从明细获取精确值；非零小额不可格式化成误导的零。
- 未知显示「— / 暂不可用」，不能与0混淆；「预估」「部分采集」「更新时间」是必要信息，不因视觉简洁删除。

## 换行与截断

- 标题、标签、错误、帮助文字允许换行；不以缩小字号、固定高度裁切或跑马灯解决溢出。长ID或路径可用 `overflow-wrap:anywhere` 视觉换行，复制内容保持完整。
- 重要状态、错误原因、按钮动作、当前选项不做省略号。非关键信息仅在已有可访问的展开/详情入口时允许单行截断；只加 `title` 不能代替完整内容入口。
- 原生Select当前值保持足够空间：至少为箭头预留40px右内边距；过长选项优先缩短文案或增加控件宽度。选项列表交给系统，不能通过CSS保证所有平台菜单一致。
- 200%浏览器缩放必须不丢内容；页面允许纵向增加并重排。桌面400px最小窗与缩放分别验收。纯文本放大、VoiceOver/Narrator及Windows原生显示是额外验收项，不能由Chrome截图推定通过。

## 文案与语义

- 产品名、实体名称与专业术语由宿主统一；配置、浏览状态与实际运行状态分别表达。
- 按钮用明确动词：「在浏览器中登录」「重新应用」「停止同步」「重试」。避免含义不明的「确定」「点击这里」。
- 状态写事实；失败写「发生了什么 + 可执行下一步」，例如「暂时无法读取列表。请检查连接后重试。」不先宣称成功，不在用户文案里展示内部堆栈或秘密。
- 表单标签始终可见，placeholder只作例子。提示和错误通过 `aria-describedby` 关联；错误同时具备文字和视觉边界。
- 文字颜色只能增强语义：主文、次文、成功、警告、错误均需可读文本。链接应有可辨识样式与键盘焦点；图标按钮需要可访问名称。
- 文本与工具栏不做入场动画；错误立即显示；数字更新不滚动计数。Select仅背景/边框120ms过渡，焦点即时，箭头保持向下，不因聚焦伪装菜单已打开。
