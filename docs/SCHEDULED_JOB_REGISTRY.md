# 只读计划与 Worker Job 登记配方

对应 GitHub issue [#190](https://github.com/linhay/rhine-design/issues/190)。这是管理后台的只读组合配方，不新增调度器、Worker API 或公共组件；计划名称、业务权限、执行记录和角色信息仍由宿主提供。

## 组合边界

- 用 `Metric` 展示有限的计划族数量、当前可见任务数量等摘要。摘要只表达同一查询范围和采集时刻，不把历史执行总量当作当前队列深度。
- 用 `Notice` 说明“只读登记表”、快照时间和权限范围。读取失败、过期或采集不完整时保留文字原因，不退化为空表。
- 用 `DataTable` 展示计划族、动态实例折叠、最近结果和 Worker 归属。表格的 `caption`、`rowKey`、排序与分页由宿主控制；库不请求、不筛选、不推断状态。
- 用 `Badge` 表达成功、失败、运行中、未知、过期和不完整等文字状态。颜色只作辅助，状态文字必须保留。
- 用 `Surface` 与 `Stack` 分组 Worker 角色卡，区分调度角色、执行角色和最近观测，不把角色卡当作实时进程列表。

推荐的只读行模型如下，`unknown` 和 `stale` 是显示语义，不是可执行控制：

```ts
type RegistryRow = {
  id: string;
  planFamily: string;
  instanceCount: number | null;
  lastOutcome: 'success' | 'failure' | 'running' | 'unknown';
  lastObservedAt: string | null;
  workerRole: string | null;
  freshness: 'current' | 'stale' | 'incomplete';
};
```

## 状态和可读性

加载时保留表头和列含义，使用 `Skeleton` 或宿主加载标记；有效空快照才显示空态。读取错误保留已确认的旧行，并在 `Notice` 中说明重试范围。未知值显示“未知”，不显示 0；没有执行记录时显示“暂无执行记录”，不推导失败率。

表格列建议为：计划族、动态实例、最近结果、最近观测、Worker 角色、数据新鲜度。历史结果可在单独列或详情区域中展开，但不能与当前队列数量混列。角色卡注明“角色登记”或“最近观测”，避免把历史心跳描述为当前进程。

## 验收边界

宿主应在 1024、1280、1440 CSS px 桌面宽度以及 200% CSS zoom 下核对：

1. 计划族身份、动态实例折叠、结果历史、Worker 归属和只读边界始终有文字依据。
2. 三个主题下表格仍能区分未知、失败、过期和不完整；不依赖颜色单独传达状态。
3. 加载、有效空、读取失败和陈旧快照互不混淆；刷新不会清空已确认的历史行。
4. 键盘可以按表格原生顺序到达表头和行内详情入口；没有隐藏的调度控制或伪造的实时进程计数。

这是合成宿主登记表的验收范围，不代表真实 Worker 服务、调度后端、屏幕阅读器或其他浏览器已由 Rhine 验证。
