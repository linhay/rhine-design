# 第三方技术文档阅读器组合

对应 [#127](https://github.com/linhay/rhine-design/issues/127)。适用于管理控制台中的 OpenAPI 阅读页：宿主负责导航、版本、状态和下载，由固定版本的标准 OpenAPI 阅读器负责规范呈现。它是可选的 Web 组合建议；下述三栏结构是该产品的明确偏好，不是所有文档页面的默认布局，也不改变[对象居中阅读](OBJECT_READING.md)的局部偏好。

**交付边界：本页仅收录规范配方，没有新增公共 API、第三方阅读器运行依赖或运行展台，新三栏阅读器及消费端浏览器验收尚未完成。** 反馈中的消费基线为 `0.11.3-accounts.4`，由反馈方报告；本库未重新验证该制品。main 文档不表示 npm 已发布或消费端已升级。

## 开发者门户三栏结构

[二次用户纠正](https://github.com/linhay/rhine-design/issues/127#issuecomment-6518728104)明确取代仅调整配色/排版的验收目标：本产品采用左侧分类接口目录、中间接口说明/参数/响应、右侧独立代码示例的开发者门户结构。宽屏并列阅读说明与示例，右栏提供语言切换及真实复制；“操作区 + Tabs + 嵌套 Swagger 折叠列表大卡片”不满足这一结构，即使字体和颜色已匹配 tokens。

用户参考为 [DeepSeek 官方 API 文档](https://api-docs.deepseek.com/api/create-chat-completion/)；2026-10-30 核对官方页面的分类导航、请求参数、响应及示例，并核对[首次调用页](https://api-docs.deepseek.com/)提供的多语言示例。本配方采用用户明确的三栏任务分工，不据此宣称参考站每个页面、窗口尺寸或版本都采用同一布局，也不推导特定阅读器或版本推荐。

| 区域 | 产品要求 |
| --- | --- |
| 左栏目录 | 按类别展示接口并标明当前项，选择后定位对应说明与示例；复用已有全局外壳，避免再嵌套一套全局导航 |
| 中栏正文 | 直接阅读当前接口、参数与响应，保留草案/实现状态、版本上下文；减少重复说明、标题和外围容器 |
| 右栏示例 | 独立于正文展示对应接口代码，语言切换保持接口上下文；复制当前语言的完整原值，真实 Promise 成功后才反馈成功，失败可重试且不执行代码 |
| 窄窗重排 | 目录收纳为可访问入口，代码区按阅读顺序重排到对应正文附近；保留导航、语言切换、复制和规范下载，表格/代码必要时局部滚动 |

列宽比例和收纳断点由消费端按真实容器确定并记录，宽屏须同时看清说明与示例，不能以空右栏或将示例藏在折叠项里冒充三栏。窄窗目录展开/选择/收起的焦点与当前项应可追踪，代码重排不得打乱说明与示例的关联或键盘阅读顺序。

消费端优先采用原生支持三栏及代码示例的标准阅读器，通过其**公开 CSS 变量**对接实际 Rhine tokens，替换上一轮大量 Swagger 局部覆盖；不自研规范解析/渲染引擎，也不要求上游引入第三方依赖。阅读器选择、精确版本、变量覆盖范围和能力缺口由消费端核实；本文不指定未经验证的实现或承诺迁移已完成。下述只读、单实例、加载代次、安全与视觉同步约束继续适用。

## 组合与所有权

| 区域 | 采用已有能力 | 宿主职责 |
| --- | --- | --- |
| 全局导航与页面 | [AppShell / SideNav](APPLICATION_COMPONENTS.md#三种外壳布局) | 页面路由、权限和返回位置；已有外壳直接复用，不嵌套第二套全局导航 |
| 同一文档的契约分区 | [Tabs](SUMMARY_TABS.md) | 区分“已实现契约 / 草案”，同时标明文档版本；草案不暗示接口可调用 |
| 加载、失败与恢复 | Notice、Button | 真实状态、超时与重试；不把错误显示为空规范，不由计时器假装就绪 |
| 规范与下载 | 原生 iframe、ButtonLink | iframe 生命周期；当前版本/分区对应的原始 OpenAPI 文件、文件名与可用状态 |

上述基础组件已存在于公开导出；按实际安装制品核对类型和契约。本配方不依赖未发布的 `Tabs fullWidth` 等新增属性。产品规范、权限判断、业务接口和下载服务留在消费项目，不进入设计库。

平级工作区已有身份时不重复大标题，文档版本留在正文上下文。操作区只放下载、重试、返回等动作，已实现/草案状态放在内容区。混合规范应在操作条目旁分别标明实现状态；不能仅用整个页面的“已实现”标签覆盖草案操作。没有规范与读取失败是不同状态；无可下载文件时明确原因，不提供无效链接。下载只导出所选规范，不执行其中描述的接口，失败仍保留阅读上下文。

## 固定资源与只读边界

第三方 JS/CSS 和规范使用宿主登记的固定版本及摘要，同源静态托管，进入阅读页后才挂载 iframe。构建锁定依赖与资源清单，不使用浮动 CDN 或外部示例地址；打包规范中的外部 `$ref`，审查 Markdown 图片/链接等外部资源，避免阅读时隐式取数。离开页面卸载阅读器并清理监听、计时器与请求。

iframe 的内部锚点只改变自己的 hash；宿主路由只由宿主导航改变，不将第三方 hash 写回顶层。独立 hash 不保证浏览器前进/后退历史也独立，实际往返路径仍需验证。主题切换不重新挂载阅读器，不丢阅读位置。

每种阅读器都须关闭在线执行、凭据输入/注入、外部校验与任意规范 URL 覆写，并按其官方文档及锁定版本验证。**以下仅是历史 Swagger UI 方案或仍使用该实现时的配置审阅示例，不是所有标准阅读器通用的选项，也不是本库初始化器或已运行的集成：**

- `supportedSubmitMethods: []` 关闭所有操作的 Try it out；`tryItOutEnabled: false` 不代替这项限制。
- `validatorUrl: 'none'` 关闭在线校验；`queryConfigEnabled: false` 禁止查询参数覆写配置，不接收任意 `url` / `configUrl`。
- `persistAuthorization: false`、`withCredentials: false`；不调用 OAuth 初始化或预授权，不传 token、不读取宿主 cookie/storage、不接入业务 client。若固定版本仍显示 Authorize 或凭据输入，需通过该版本支持的插件/布局去除交互并实际验证；仅关闭持久化不能满足“无凭据”。认证方案仍可作为静态契约说明保留。

上述 Swagger 选项含义见 [Swagger UI 官方配置](https://swagger.io/docs/open-source-tools/swagger-ui/usage/configuration/)（2026-10-30 核对）；更换阅读器须重新核对等价限制，不直接照抄这些选项。关闭执行控件不是网络隔离；采用预先打包的规范对象和静态资源，按部署配置 CSP 限制请求、表单及嵌入目标，并以浏览器网络记录核对只出现登记的文档资源、没有业务请求和外部校验。同源 iframe 的页面/静态资源请求仍可能自动携带同源 cookie；Swagger 的 `withCredentials: false` 也不保证零 cookie。不得向阅读器注入授权凭据；如要求所有请求完全无 cookie，必须另行设计无 cookie 的部署边界并验证，不能据此配置宣告完成。

同源 iframe 提供文档、样式及 hash 的组织隔离，不是运行不可信代码的安全边界。不要将 `sandbox="allow-scripts allow-same-origin"` 当作同源代码的安全保证；只嵌入审查过的固定静态资源，不允许规范切换任意脚本或页面。iframe 与 sandbox 的限制见 [HTML 标准的 iframe 规则](https://html.spec.whatwg.org/multipage/iframe-embed-object.html#attr-iframe-sandbox)。产品若需要不可信规范或跨源托管，须重新设计并独立验收，不直接套用本配方。

## 宿主规范与阅读器内部适配

[用户纠正](https://github.com/linhay/rhine-design/issues/127#issuecomment-6517576197)替代此前“标准渲染区保持自身配色、宿主主题只影响外壳”的约定：**宿主规范优先，第三方默认视觉不是例外。** 本产品要求阅读正文也遵循实际安装 Rhine 制品的字体、字号/行高/字重、间距、色彩、圆角和焦点 tokens。其他宿主按自己的阅读需求选择是否采用这一局部适配；不能把被取代的浅色方案继续作为本产品默认。

保留标准 OpenAPI 渲染引擎及 iframe 隔离，在阅读器文档内部按锁定版本的公开 CSS 变量维护语义映射。按实际安装版本核对 [tokens](../components/tokens.css)、[字体](../components/TYPOGRAPHY.md)、[间距](../components/SPACING.md)及[主题契约](THEMING.md)，把正文、路径、响应表、代码、操作与焦点映射到对应语义；不复制 main 的未发布值、不硬编码另一套尺寸/配色，也不让宿主全局选择器穿透覆盖第三方 DOM。iframe 的 CSS 不自动继承父文档变量；内部显式加载同一固定制品的可用主题/tokens 并局部适配，或由宿主传递经过白名单校验的实际语义值。具体传递与样式映射由消费端维护，不是新增公共主题桥接 API，也不要求改变设计库组件或依赖。历史 Swagger 局部选择器覆盖不作为新阅读器的通用映射方案；公开变量未覆盖的能力须如实记录缺口，不能宣称任意第三方升级都兼容。

宿主拥有三主题和减少动态偏好，阅读器内部同步当前视觉状态。更新只作用于当前存活 reader 的主题属性、语义变量和动态偏好，不修改 iframe `src`、重挂 key、递增加载代次、重新解析规范或重建阅读器；保持展开状态、焦点与滚动位置。主题和系统/宿主减少动态的初始值及后续变化均需同步，消息沿用当前 frame/来源/结构校验，丢弃过期视觉更新，不能用就绪时捕获的旧偏好覆盖最新选择。动态规则遵循[动效契约](../components/MOTION.md)，不新增阻塞阅读的切换动画。

长路径可换行但复制保持原值，响应表和代码保持可读、可选择/复制；窄窗需要时在对应内容块内局部滚动，保留末列/末行可达，不缩小字号、裁正文或把整个宿主页面撑宽。正文语义和必要状态不因视觉适配被删除；局部样式随阅读器版本维护，不能宣称任意第三方升级都兼容。

## 加载、版本切换与消息

Tabs 的非活动面板使用 `hidden`，仍保留全部 `item.content` 子树（见 [Tabs 实现](../components/components.tsx)）；隐藏不等于按需挂载，也不会阻止其中的 iframe 加载。不要给每个 item 都传同一个 reader 或把多个 iframe 绑定同一 ref。宿主只给当前活动 item 提供阅读器内容，其他 item 的 `content` 为 `null`；保留 Tabs 的页签/面板关系及现有键盘语义，无须改变公共组件的隐藏行为。

```tsx
// activeSection、sections 和 reader 均由宿主管理；reader 是当前版本/加载代次的唯一 iframe。
const items = sections.map(item => ({
  ...item,
  content: item.value === activeSection ? reader : null,
}));
```

页面未进入时不挂载 reader；进入后最多一个 iframe。版本/分区/重试导致重建时，旧 reader 的卸载清理不得清空新 reader 的 ref 或监听；消息处理始终读取当前存活 iframe 的 ref，不能闭包捕获旧实例。按文档身份和加载代次建立 key/清理归属，核对活动面板内唯一 reader、隐藏面板无 iframe、ref 指向该存活实例及实际资源请求数量；仅数可见 iframe 不足以证明按需挂载。

宿主至少维护文档 id、版本、实现分区、加载代次与 `loading / ready / error`。每次切版本或重试递增加载代次并销毁旧 iframe；切换入口立即显示新目标的加载状态，不能让旧规范顶着新版本标题出现。若保留旧内容，必须标明它所属的旧版本，并且下载继续绑定其明确的版本，不能混用。

iframe 的 `load` 只说明导航事件，不能证明资源、规范解析或渲染成功；浏览器也不会可靠地以 iframe `error` 报告加载失败，见 [HTML 标准的 iframe 事件规则](https://html.spec.whatwg.org/multipage/iframe-embed-object.html#the-iframe-element)。由宿主控制的阅读器包装页在初始化、规范解析和可读内容提交完成后报告就绪，捕获失败并设置有界超时。所选阅读器的回调与错误覆盖需按固定版本实现验证，不能假设 `load` 或某一个回调覆盖所有失败。

需要 `postMessage` 时，消息只承载约定的就绪/错误/返回意图、经校验的主题/动态偏好及文档标识，不传凭据、任意 HTML 或导航 URL。双方使用精确 `targetOrigin`；宿主同时校验 `event.origin`、`event.source === 当前 iframe.contentWindow`、消息结构、文档/版本/分区及当前加载代次。旧 iframe 的迟到 ready/error 均丢弃。校验原则见 [HTML 标准的消息安全规则](https://html.spec.whatwg.org/multipage/web-messaging.html#security-postmsg)；版本/代次校验是本配方的宿主约束，不是浏览器自动提供的保证。

失败用持续的 Notice 说明目标与下一步，允许重试、切版本和返回；重试创建新代次，不能由旧消息抹掉新错误。卸载、切版本与重试都取消旧请求和超时，撤销旧监听。有效的下载可以独立保留，但必须明确它是当前可用文件，不能因渲染失败就改为另一版本。

## 键盘、滚动与验收

iframe 提供包含文档身份的 `title`，外侧保留进入阅读器、下载及返回宿主入口，包装页内提供可用键盘到达的“返回文档工具栏”动作。通过校验后的返回意图将焦点交给存活的宿主入口；普通就绪消息不抢焦点。Tab / Shift+Tab 能进入和离开 iframe，不截获全局 Escape、不建立键盘陷阱；从含 iframe 的 Tabs 面板切走后，隐藏内容不能继续进入 Tab 顺序。重建正在持有焦点的 iframe 前，先交接至所选版本/分区入口，避免焦点掉到 BODY。

宿主正文与阅读器内部明确各自滚动归属；有界 flex/grid 区域设置可收缩轨道及 `min-height: 0`，iframe 保持可用正文高度，不以隐藏溢出遮掉长路径、代码或最后一项。长代码可在内部横滚，外壳标题、状态、版本和下载动作须换行或滚动可达。切主题保持位置；文档/版本/分区之间由宿主明确重置或按身份恢复位置，不能误恢复另一规范的坐标。

本轮只证明规范内容和链接；下表是消费端真实集成的验收要求，**均未因本文合入而获得 PASS**。示意或合成 iframe 只能证明所测宿主行为，不能替代所选标准阅读器的实际集成。

| 场景 | 必须观察的结果 |
| --- | --- |
| 宽屏三栏与接口导航 | 记录真实容器及三栏宽度/比例；分类目录可选择并定位当前接口，中间说明/参数/响应与右侧独立示例同时可读；无重复全局导航、标题或嵌套大卡片占用 |
| 示例语言与真实复制 | 语言切换更新对应接口示例且不丢阅读位置；实际剪贴板内容等于当前语言完整代码，失败不显示成功，不执行示例；合成复制不能替代此项 |
| 窄窗目录与代码重排 | 记录断点和实际内宽，目录入口及选择/收起焦点可达，代码按对应正文重排；导航、状态、下载、语言与复制保留，无整页横溢或内容裁切 |
| 初载、脚本/CSS/规范失败、解析失败、超时、重试 | 准确状态、可见错误与可执行恢复；`load` 不提前置 ready；旧 ready 不掩盖新失败 |
| 快速 A→B→A、重试、卸载 | 活动面板内唯一 reader，隐藏面板无 iframe，当前 ref 与请求归属正确；旧代次/旧来源消息无效；标题、规范、状态和下载一致；监听/超时/请求释放 |
| 已实现/草案与下载 | 每个分区及混合条目状态真实；下载版本、内容和文件名一致，失败不丢上下文 |
| 只读与网络 | 没有执行/凭据入口，无业务请求、凭据注入、外部校验或未登记资源；实际记录 cookie 边界 |
| 路由与主题 | 阅读器锚点不改宿主 hash；浏览器前进后退符合约定的宿主/阅读器往返路径；阅读正文语义样式与实际安装 tokens 对应；三主题切换不重新请求/解析规范、不重建 reader，展开/焦点/滚动保留 |
| 键盘与辅助技术 | 正反向进入/返回、隐藏面板退出焦点序列、切版本安全交接；实际读屏名称和阅读顺序另验 |
| 窄宽、短屏、长文与滚动 | 宿主支持的主题（反馈为三主题）、400/520/880 宽及 200% 缩放下，入口/状态/下载可达，长路径复制完整，响应表末列和代码末行/横滚可达，局部滚动不撑宽宿主；记录实际 iframe 内宽 |
| 减少动态与位置 | 正常及系统/宿主减少动态下走同一阅读恢复路径，无非必要入场阻塞；系统/宿主偏好切换不重载或丢展开/焦点/位置，返回的位置策略符合约定 |

验收记录绑定实际宿主源码、Rhine 制品、所选阅读器名称及精确版本、规范与资源摘要、浏览器及构建，区分 PASS / FAIL / SKIPPED / N/A。CSS zoom 与浏览器原生缩放分别记录；主库组件测试或静态截图不外推实际阅读器、读屏、其他引擎或真实产品验收。

规范纠正与内容/链接检查构成本库本次文档交付；消费端真实集成验收独立记录，不以未来回填作为规范收录完成的前提，也不把未验证项目记为 PASS。

## 消费反馈的证据归属

[后续消费反馈](https://github.com/linhay/rhine-design/issues/127#issuecomment-6517461845)报告使用固定 Swagger UI `5.34.0`，以合成数据完成现行/草案文件、实际下载、按需加载、只读网络及 Chromium 三主题、400/520/880 宽、100%/200% CSS zoom、键盘、减少动态、失败重试和单 reader 检查；其他浏览器及原生浏览器缩放未验证，未宣称生产发布。这是消费方自报的版本限定结果，本库本轮仅核对评论、Tabs 源码和规范，未独立复验该集成，也不将该版本宣布为通用推荐或 npm 能力。

随后[用户确认的产品要求](https://github.com/linhay/rhine-design/issues/127#issuecomment-6517576197)取代该反馈中的“阅读器自身浅色”视觉约定，要求正文遵循实际 Rhine tokens 并同步三主题/减少动态。[旧 Swagger tokens 适配自报](https://github.com/linhay/rhine-design/issues/127#issuecomment-6517765790)记录了其原修订的排版、主题同步和 Chromium 验证；该结果不能证明[后续三栏目标](https://github.com/linhay/rhine-design/issues/127#issuecomment-6518728104)已完成。主题符合 tokens 不等于信息架构符合新要求；三栏比例、导航、语言切换、真实复制和窄窗重排仍需新阅读器的真实消费验收。本库收录的是修正后的规范与局部适配边界，未运行新阅读器，也未发布组件能力或升级消费制品。
