# 第三方技术文档阅读器组合

对应 [#127](https://github.com/linhay/rhine-design/issues/127)。适用于管理控制台中的 OpenAPI 阅读页：宿主负责导航、版本、状态和下载，固定版本的 Swagger UI 负责规范呈现。它是可选的 Web 组合建议，不是所有文档页面的默认布局，也不改变[对象居中阅读](OBJECT_READING.md)的局部偏好。

**交付边界：本页仅收录规范配方，没有新增公共 API、Swagger UI 依赖或运行展台，尚未完成真实阅读器及消费端浏览器验收。** 反馈中的消费基线为 `0.11.3-accounts.4`，由反馈方报告；本库未重新验证该制品。main 文档不表示 npm 已发布或消费端已升级。

## 组合与所有权

| 区域 | 采用已有能力 | 宿主职责 |
| --- | --- | --- |
| 全局导航与页面 | [AppShell / SideNav](APPLICATION_COMPONENTS.md#三种外壳布局) | 页面路由、权限和返回位置；已有外壳直接复用，不嵌套第二套全局导航 |
| 同一文档的契约分区 | [Tabs](SUMMARY_TABS.md) | 区分“已实现契约 / 草案”，同时标明文档版本；草案不暗示接口可调用 |
| 加载、失败与恢复 | Notice、Button | 真实状态、超时与重试；不把错误显示为空规范，不由计时器假装就绪 |
| 规范与下载 | 原生 iframe、ButtonLink | iframe 生命周期；当前版本/分区对应的原始 OpenAPI 文件、文件名与可用状态 |

上述基础组件已存在于公开导出；按实际安装制品核对类型和契约。本配方不依赖未发布的 `Tabs fullWidth` 等新增属性。产品规范、权限判断、业务接口和下载服务留在消费项目，不进入设计库。

标题附近保留文档身份、版本和实现状态，避免重复外壳页名。混合规范应在操作条目旁分别标明实现状态；不能仅用整个页面的“已实现”标签覆盖草案操作。没有规范与读取失败是不同状态；无可下载文件时明确原因，不提供无效链接。下载只导出所选规范，不执行其中描述的接口，失败仍保留阅读上下文。

## 固定资源与只读边界

第三方 JS/CSS 和规范使用宿主登记的固定版本及摘要，同源静态托管，进入阅读页后才挂载 iframe。构建锁定依赖与资源清单，不使用浮动 CDN 或外部示例地址；打包规范中的外部 `$ref`，审查 Markdown 图片/链接等外部资源，避免阅读时隐式取数。离开页面卸载阅读器并清理监听、计时器与请求。

Swagger UI 使用独立文档及自己的可读配色；宿主主题只影响外壳，不把 `.rhine-theme`、CSS 变量或全局覆盖注入其内部。iframe 的内部锚点只改变自己的 hash；宿主路由只由宿主导航改变，不将第三方 hash 写回顶层。独立 hash 不保证浏览器前进/后退历史也独立，实际往返路径仍需验证。主题切换不重新挂载阅读器，不丢阅读位置。

只读配置至少核对以下项目，具体支持情况以宿主锁定版本为准。以下是配置审阅要点，不是本库提供的初始化器或已经运行的集成示例：

- `supportedSubmitMethods: []` 关闭所有操作的 Try it out；`tryItOutEnabled: false` 不代替这项限制。
- `validatorUrl: 'none'` 关闭在线校验；`queryConfigEnabled: false` 禁止查询参数覆写配置，不接收任意 `url` / `configUrl`。
- `persistAuthorization: false`、`withCredentials: false`；不调用 OAuth 初始化或预授权，不传 token、不读取宿主 cookie/storage、不接入业务 client。若固定版本仍显示 Authorize 或凭据输入，需通过该版本支持的插件/布局去除交互并实际验证；仅关闭持久化不能满足“无凭据”。认证方案仍可作为静态契约说明保留。

配置含义见 [Swagger UI 官方配置](https://swagger.io/docs/open-source-tools/swagger-ui/usage/configuration/)（2026-10-30 核对）。关闭执行控件不是网络隔离；采用预先打包的规范对象和静态资源，按部署配置 CSP 限制请求、表单及嵌入目标，并以浏览器网络记录核对只出现登记的文档资源、没有业务请求和外部校验。同源 iframe 的页面/静态资源请求仍可能自动携带同源 cookie；`withCredentials: false` 不保证零 cookie。不得向阅读器注入授权凭据；如要求所有请求完全无 cookie，必须另行设计无 cookie 的部署边界并验证，不能据此配置宣告完成。

同源 iframe 提供文档、样式及 hash 的组织隔离，不是运行不可信代码的安全边界。不要将 `sandbox="allow-scripts allow-same-origin"` 当作同源代码的安全保证；只嵌入审查过的固定静态资源，不允许规范切换任意脚本或页面。iframe 与 sandbox 的限制见 [HTML 标准的 iframe 规则](https://html.spec.whatwg.org/multipage/iframe-embed-object.html#attr-iframe-sandbox)。产品若需要不可信规范或跨源托管，须重新设计并独立验收，不直接套用本配方。

## 加载、版本切换与消息

宿主至少维护文档 id、版本、实现分区、加载代次与 `loading / ready / error`。每次切版本或重试递增加载代次并销毁旧 iframe；切换入口立即显示新目标的加载状态，不能让旧规范顶着新版本标题出现。若保留旧内容，必须标明它所属的旧版本，并且下载继续绑定其明确的版本，不能混用。

iframe 的 `load` 只说明导航事件，不能证明资源、规范解析或渲染成功；浏览器也不会可靠地以 iframe `error` 报告加载失败，见 [HTML 标准的 iframe 事件规则](https://html.spec.whatwg.org/multipage/iframe-embed-object.html#the-iframe-element)。由宿主控制的阅读器包装页在初始化、规范解析和可读内容提交完成后报告就绪，捕获失败并设置有界超时。Swagger 的回调与错误覆盖需按固定版本实现验证，不能假设 `load` 或某一个回调覆盖所有失败。

需要 `postMessage` 时，消息只承载约定的就绪/错误/返回意图及文档标识，不传凭据、任意 HTML 或导航 URL。双方使用精确 `targetOrigin`；宿主同时校验 `event.origin`、`event.source === 当前 iframe.contentWindow`、消息结构、文档/版本/分区及当前加载代次。旧 iframe 的迟到 ready/error 均丢弃。校验原则见 [HTML 标准的消息安全规则](https://html.spec.whatwg.org/multipage/web-messaging.html#security-postmsg)；版本/代次校验是本配方的宿主约束，不是浏览器自动提供的保证。

失败用持续的 Notice 说明目标与下一步，允许重试、切版本和返回；重试创建新代次，不能由旧消息抹掉新错误。卸载、切版本与重试都取消旧请求和超时，撤销旧监听。有效的下载可以独立保留，但必须明确它是当前可用文件，不能因渲染失败就改为另一版本。

## 键盘、滚动与验收

iframe 提供包含文档身份的 `title`，外侧保留进入阅读器、下载及返回宿主入口，包装页内提供可用键盘到达的“返回文档工具栏”动作。通过校验后的返回意图将焦点交给存活的宿主入口；普通就绪消息不抢焦点。Tab / Shift+Tab 能进入和离开 iframe，不截获全局 Escape、不建立键盘陷阱；从含 iframe 的 Tabs 面板切走后，隐藏内容不能继续进入 Tab 顺序。重建正在持有焦点的 iframe 前，先交接至所选版本/分区入口，避免焦点掉到 BODY。

宿主正文与阅读器内部明确各自滚动归属；有界 flex/grid 区域设置可收缩轨道及 `min-height: 0`，iframe 保持可用正文高度，不以隐藏溢出遮掉长路径、代码或最后一项。长代码可在内部横滚，外壳标题、状态、版本和下载动作须换行或滚动可达。切主题保持位置；文档/版本/分区之间由宿主明确重置或按身份恢复位置，不能误恢复另一规范的坐标。

本轮只证明规范内容和链接；下表是消费端真实集成的验收要求，**均未因本文合入而获得 PASS**。示意或合成 iframe 只能证明所测宿主行为，不能替代 Swagger 实际集成。

| 场景 | 必须观察的结果 |
| --- | --- |
| 初载、脚本/CSS/规范失败、解析失败、超时、重试 | 准确状态、可见错误与可执行恢复；`load` 不提前置 ready；旧 ready 不掩盖新失败 |
| 快速 A→B→A、重试、卸载 | 旧代次/旧来源消息无效；标题、规范、状态和下载一致；监听/超时/请求释放 |
| 已实现/草案与下载 | 每个分区及混合条目状态真实；下载版本、内容和文件名一致，失败不丢上下文 |
| 只读与网络 | 没有执行/凭据入口，无业务请求、凭据注入、外部校验或未登记资源；实际记录 cookie 边界 |
| 路由与主题 | 阅读器锚点不改宿主 hash；浏览器前进后退符合约定的宿主/阅读器往返路径；主题切换不重建或丢位置 |
| 键盘与辅助技术 | 正反向进入/返回、隐藏面板退出焦点序列、切版本安全交接；实际读屏名称和阅读顺序另验 |
| 窄宽、短屏、长文与滚动 | 宿主支持的主题（反馈为三主题）、400/520/880 宽及 200% 缩放下，入口/状态/下载可达，内外末项与代码横滚可达，滚动相互独立；记录实际 iframe 内宽 |
| 减少动态与位置 | 正常及系统/宿主减少动态下走同一阅读恢复路径，无非必要入场阻塞；切主题/返回的位置策略符合约定 |

验收记录绑定实际宿主源码、Rhine 制品、Swagger UI 精确版本、规范与资源摘要、浏览器及构建，区分 PASS / FAIL / SKIPPED / N/A。CSS zoom 与浏览器原生缩放分别记录；主库组件测试或静态截图不外推实际阅读器、读屏、其他引擎或真实产品验收。
