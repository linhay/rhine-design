# 异步快照与模块加载

对应 [#116](https://github.com/linhay/rhine-design/issues/116) 及其后续评论。真实展台 `/#async-snapshot-recipes`，隔离生产入口 `/?fixture=async-snapshot-recipes`。这是账号/资源列表和只读诊断的宿主组合配方，复用公开 Tabs、Skeleton、Surface、Stack、Grid、Inline、Notice、DataTable、CopyButton，没有新增公共缓存框架、请求 API 或动画。源码展台不表示 npm 发布或原消费必须升级；下述完整历史窗口是后续规范补充，尚未由该展台实现或验证。

## 快照、请求和结果归属

- 已有快照立即可读，同范围后台读取不覆盖内容。无快照读取中显示符合真实卡片六模块的 Skeleton，不先显示伪造的 0 条、0 额度或成功空态。只有一次完成且有效的空响应才显示空结果。
- **本场景的最新 Tab 偏好取代泛化的更新提示建议**：切换 Tab 时顶部计数/时间逐字保留上一份摘要，不追加“正在更新结果”，列表读取按钮不跟着旋转；当前 Tab 的真实结果面板显示骨架。摘要明确写出旧快照所属分类，旧的“全部”计数不能冒充新的 OAuth 结果。新响应被接受后才更新摘要。搜索/其他筛选反馈独立，不被该 Tab 规则抹去。
- 观测时间来自快照；不以渲染时刻、读取尝试时间或恢复显示伪造 freshness。过期、读取失败、暂停、预算耗尽与有效空结果分别表达。读取失败保留旧快照和原任务状态，并提供重试；无快照失败不显示成功空态。
- **预算耗尽不等于请求失败**：已有可用快照时，用 Notice 的中性信息语义说明“旧快照仍可读，稍后可重试更新”，保留原观测时间与 paused/failed 任务状态，不将旧值标为实时；无快照预算耗尽仍明确未知且退出骨架，不能成为成功空态。真正请求失败继续用错误语义。只有摘要属于旧范围时，当前面板仍明确尚无快照，不显示“旧快照仍可读”；摘要继续保留原范围归属。重试按钮若持有焦点，激活时先将焦点交给稳定的“读取现有结果”入口，避免提示卸载后落到 BODY；完成时不抢回外部焦点。两种预算场景都提供显式重试，沿用同一有界读取与取消规则。
- 动作区只放动作，元信息在相关结果说明/内容区。“读取现有结果”只读当前列表；“更新此对象”是另一个有显式含义的对象操作，名称和忙态分开。展台对象更新是标明的合成计时器，不代表后台执行。

示例宿主 `preview/asyncSnapshotRecipe.ts` 在范围变化、隐藏、手动暂停和卸载时 abort，并用生命周期/epoch 双重丢弃不响应 AbortSignal 的迟到结果。隐藏页面暂停，恢复后重读；手动暂停不会被可见性恢复绕过。待生成结果本轮最多读取三次，随后退出忙态并提供新一轮重试，取消退避计时器。真实后端权限、预生成、预算、缓存策略和调度由产品负责；不要复制本展台参数作为通用默认。

对象移除证据同样有有效期，失败与过期不能推断移除，见[对象生命周期配方](OBJECT_LIFECYCLE.md)。该配方只用于仍需历史的场景；已确认全部退役且无历史需求时使用现有空态，不保留快照读取或轮询依赖。

## 六个稳定槽位

身份、额度、时间/状态、历史、费用、操作各用相同网格槽位与响应式 **min-height** 组合加载/完成/失败。它们是此合成账号卡片的局部尺寸选择，不是通用组件固定高度。

已知内容局部加载时保留实际布局，内容用 `visibility:hidden`、`aria-hidden` 与 `inert` 排除视觉和键盘交互，公开 Skeleton 占同一网格区域。首次未知内容仅有区域骨架及最小高度；极窄容器增加换行预留。不能承诺任意未知长数据首次补齐零位移；文本完整优先，允许自然撑高，不用固定 height/overflow:hidden、缩字号或裁值制造稳定。

模块读取所有权相互独立：已有历史或局部缺桶保留已知值；历史读取失败保留旧历史。费用仅缺部分字段时按字段占位，保留已知金额、优先级和关联 Key，不因额度有缓存就宣称费用齐全。读取仍在进行时缺失字段用 Skeleton，完成但字段仍缺失时退出骨架并明示未知；不把成功读取一份部分 DTO 当成所有字段齐全，也不永久旋转等待。不提供额度的 API Key 明示“不提供额度”，退出骨架；未知额度显示未知，不能是 0 或永久 loading。费用辅助字段复用所属列轨道。紧凑时间和只读标签沿用[列表卡片配方](LIST_CARD_RECIPES.md)。

## 完整历史窗口与局部时间桶

[#116 的时间轴补充](https://github.com/linhay/rhine-design/issues/116#issuecomment-6518630873)是该消费场景的新验收约束，补充此前仅保留旧历史的约定；不要求所有列表预取全部历史，也不向通用库增加时间桶算法或数据层实现承诺。

- 宿主对完整历史窗口维护同一份已处理真源，较短时间视图只切片该结果；切换视图不建立独立统计口径或相互覆盖的缓存真源。统一处理不等于一次性下载全部原始记录。
- 先显示当前范围可用缓存，再按缺口补齐。单桶读取失败或待补只影响该桶，保留其他桶已接受的值；同桶有旧值时保留其值及原观测时间，另标过期、待补或读取失败。大范围失败才增加模块级反馈，仍不清空可用结果；范围判定由宿主定义并验收，不能用任一桶失败触发整窗未知。
- 缺失、读取中、过期、读取失败、真实未知与完整统计下的零请求分别表达。读取失败可以与旧值并存；读取完成也可能仍缺请求标识或最终结果而保持未知。已有用量记录及 WebSocket 记录数不等于可去重请求总数，不能凭费用/输出推断成功率或为填色补出 0%。跨桶去重和真实未知语义继续保留，见[部分数据反馈](https://github.com/linhay/rhine-design/issues/116#issuecomment-6517573409)。
- 接受结果时校验范围、窗口、桶的时间归属及请求代次；取消或过期响应不能覆盖新窗口，也不能把旧范围缓存挂到新范围。切片和后台补齐遵循同一归属规则。
- 邻近缺口合并、批量读取/处理、并发、内存与重试预算均由宿主数据层管理；预算用尽退出忙态，保留可用值和真实缺口，允许显式重试。统一窗口不要求逐分钟发请求，不以无限轮询换取表面完整，也不沿用合成展台的三次读取参数作为生产预算。

消费端须用同一完整窗口核对长短视图一致、单桶失败/待补不污染邻桶、大范围失败仍保留已接受值、缓存先行及缺失/过期/失败/真实未知/有效零值的区分、跨桶去重、快速换窗口与迟到保护；另记录批量、并发、内存和重试在实际数据规模下的预算与结果。**新消费实现及资源验证尚未完成**；本节合入仅完成规范收录，既有合成展台、测试和旧消费结果不证明新时间桶算法、资源预算或生产缺陷已修复。

## 只读诊断

分别表达任务 `failed/paused`、读取状态和是否旧快照。保留旧 DTO 时，读取失败不把原 failed/paused 改成成功；没有快照的 loading/error 也不显示成功空态。未知覆盖率和空路径不等于健康/全覆盖；未提供业务观测时间就明示缺失，不合成时间。

命令区只复制，不执行。实际宿主将真实复制 Promise 交给公开 CopyButton，await 成功后才显示“已复制”；失败显示可重试错误。展台明确标为 **mock 复制**，用可清理 Promise 演示成功/失败，不访问业务剪贴板。无命令时无复制入口；路径使用 DataTable 局部滚动，保留最后列可达。

## 消费来源与性能边界

[#116 的后续消费反馈](https://github.com/linhay/rhine-design/issues/116#issuecomment-6516406702) 区分正式制品固定 accounts.2 与共享开发树 accounts.4；两者各自验证，不能用开发依赖推断正式入口的实际消费版本。首次冷下载新版本懒资源与热缓存数据读取是独立关键路径，热读改善不证明首次进入也已完成同等性能验收。本展台仅验证合成状态组合，不测量真实产品的冷/热性能。

## 验收边界

运行 `tests/AsyncSnapshotRecipes.test.tsx` 和生产预览上的 `scripts/check-async-snapshot-recipes.js`。检查三主题、400/520/880×100/200% CSS zoom、六模块逐个/全部加载同宽 top/height、长文自然增高、内框及滚动末项、非活动和 inert 内容的真实 Tab 顺序。检查实际快速切换/旧响应、隐藏暂停恢复（浏览器测试显式模拟 visibility 事件）、三次预算退出与重试、旧历史失败、未知/不提供额度和部分费用、复制 Promise 正反向。正常/系统/手动减少动态完成同一路径，正常 Skeleton 脉动而减少动态静止。

有针对性的槽位裁切/伪新 Tab 归属反例应命中；异常和超时不是反例成功。保留首次失败。JSDOM/mock、静态截图及 CSS zoom 不证明真实服务、浏览器原生缩放、读屏语音、触摸硬件、真实后台节流或原生平台行为。

## 对象设置与人员目录读取

承接[#116 设置读取反馈](https://github.com/linhay/rhine-design/issues/116#issuecomment-6519086674)：对象设置的关键读取不等待无关通知端点。彼此独立的请求按各自结果展示错误/重试；通知慢或失败不将已就绪的表单继续锁住，也不把设置失败装成成功或填入默认值。

已选人员的可见姓名应随设置快照一并返回并保持稳定身份，避免先展示内部 ID，再等待候选搜索补名字。搜索/分页继续走服务端，不能把已选快照当作完整可选目录或在前端替代真实查询。姓名缺失或目录成员变化时明示未确认/不可用状态，不编造姓名；已选标签的显示快照不授予操作权限。

目录快照复用与逐请求授权是不同职责：读设置、搜人员、保存分配都由服务端按当前权限校验。目录版本变化、人员删除、授权撤销均须重新核对；旧目录快照或已选姓名不能绕过鉴权。范围/对象/查询代次与取消、迟到保护继续由宿主实现，旧对象结果不能挂到新对象；错误保留有归属的可用草稿，未接受的结果不显示成功。

合成 `?fixture=settings-dialog&object=1` 只证明设置先就绪、姓名初次显示、通知独立失败及子表单完成同步；候选为明确标记的内存模拟，没有实现或证明真实服务端搜索、目录缓存、授权撤销或后端性能。真实宿主须另验冷/热目录、目录变化/撤权、慢通知、读取失败、快速换对象/查询和迟到响应；记录入口到表单可用、姓名首次可见的完整耗时，区分首次懒资源下载与热缓存。不能用接口耗时或本展台的合成计时器宣称整页“秒开”。
