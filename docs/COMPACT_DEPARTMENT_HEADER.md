# 紧凑部门导航栏与图标动作配方

对应 GitHub issue [#192](https://github.com/linhay/rhine-design/issues/192)。这是组织目录宿主的紧凑导航栏配方，不改变 Rhine 公共 API，也不把部门、成员或权限模型引入组件库。

## 结构

将部门名称和成员摘要放在同一导航栏行中，使用一个底部分隔线承接内容 Tab。不要重复渲染“当前部门”标题或额外卡片标题；部门名称本身是层级起点，成员摘要是同一行的上下文说明。

右侧只保留两个相邻的 `IconButton`：

```tsx
<Inline className="department-header__actions" gap={0}>
  <IconButton icon="moreVertical" label="更多部门操作" title="更多部门操作" />
  <IconButton icon="plus" label="新增人员" title="新增人员" />
</Inline>
```

动作组使用 `display: flex`、`flex-wrap: nowrap` 和两个 44×44 CSS px 命中区域。不要给按钮再套一层带 padding 的 Button，也不要让窄列把两个动作折成竖排。部门名称允许换行，动作组保持固定在行末；长名称与 200% CSS zoom 时由标题区域收缩，而不是挤压命中区域。

## 对话框上下文

“新增人员” Dialog 在当前部门上下文打开：当前部门是只读字段，并明确提示人员默认归属该部门；创建前必须手动选择单一“目标分组”。分组选项可显示部门优先标记和资格人数，但分组只用于候选展示和运营管理，不改变部门归属或权限。

“调整部门”使用现有双栏 Rhine Dialog split：左侧选择目标部门，右侧同时显示人员、当前部门、目标部门和影响范围。取消与保存都可达；保存只改变组织目录归属及后续用量归属，不修改 API-Key 或历史用量。

## 验收边界

在窄桌面内容列、1280/1440 CSS px 以及 200% CSS zoom 下核对：

- 部门名称与成员摘要仍共享一条清晰基线，底部分隔线承接内容 Tab。
- 两个图标动作始终同排、各自有可见 title 和可访问名称，键盘 Tab 顺序为更多操作后新增人员。
- 长名称自然换行且不产生横向溢出；动作组不被裁剪、不依赖颜色传达含义。
- Dialog 关闭后焦点回到触发按钮；只读部门字段、单选目标分组和双栏调整部门语义保持清楚。

本配方使用合成组织目录；真实人员服务、权限后端、API-Key 和历史用量更新仍由消费项目单独验收。
