# 局部长文排版配方

[#150](https://github.com/linhay/rhine-design/issues/150) 的书卷方向本轮采用现有纸面主题与局部正文配方，不新增 ThemeName、Reader、Prose 或可调阅读器。当前公开导出没有 `Reader` / `Prose`；[对象阅读](OBJECT_READING.md)由 Dialog、Tabs、Text 和宿主状态组合。这里的排版可用于普通文章或既有 Dialog 正文，不改变工具栏、页签与操作控件，不扩大 Dialog 的 480px 最大宽度。

本页收录可独立核验的组合，不宣称新字体更舒适、阅读更快或真人偏好已确认。继续使用系统字体和既有纸面配色；不引入远端字体、语言过滤、摘要引擎或内容持久化服务。以下数值是局部样例，不是全库默认，也不代表 npm 新增能力。

## 组合

使用语义化 `article`、段落、标题、列表、引用等原生元素与公开 Text。宿主给每段稳定身份，重复文字也不能共用 id。`lang` 只标注语言；原文、英文、数字、单位、代码与链接保持完整，不因语言或主题被过滤。

```tsx
import { Text } from '@linhey/rhine-design';

<article className="rhine-reading-example" lang="zh-CN" aria-label="观察记录">
  <Text as="h2" variant="heading">观察记录</Text>
  <Text id="record-p01">正文、24.8 ms 和 request_id_742 保留原值。</Text>
  <Text lang="en" id="record-p02">The source paragraph remains available.</Text>
</article>
```

```css
/* 应用自己的局部配方；不覆盖组件私有选择器。 */
.rhine-reading-example {
  --rhine-text-body: 16px;
  --rhine-leading-body: 28px;
  font-size: 16px;
  line-height: 1.75;
  max-inline-size: 34em;
  min-inline-size: 0;
  margin-inline: auto;
  overflow-wrap: anywhere;
  text-align: start;
}
.rhine-reading-example > * + * { margin-block-start: 1em; }
```

正文中的独立代码块、必要二维表格用宿主有名称、可键盘到达的局部横滚区；正文和长链接仍换行。表格单元格不能因表格可横滚就任意裁切。图片提前提供正确宽高或比例，避免加载后推走正文。不要在正文外层加入固定高度与隐藏溢出来掩盖问题。

配方作用于正文子树；放在这里的按钮仍使用其原有控件契约。若把额外控件放进正文，需检查它们是否继承了局部文字变量；工具栏与页签应留在正文之外。

## 行长是容器结果

基于 `97cc8282cad4bcb5b92555648d441622c0caba31` 的固定未发布包，新安装合成文章的 Chromium 实测如下。文章用同一段连续全角汉字，按 Range 的实际行片段计数；不是用容器宽度直接除字号，也不把标点与混排的行长强行等同。

| 视口，CSS zoom 1 | 独立正文内宽 / 整行字数 | 普通 Dialog 正文内宽 / 整行字数 |
| --- | --- | --- |
| 320px | 288px / 18 | 238px / 14 |
| 400px | 368px / 23 | 318px / 19 |
| 520px | 488px / 30 | 430px / 26 |
| 880px | 544px / 34 | 430px / 26 |

正文为16px；另测18px时，400px Dialog为17字，880px Dialog为23字。28–34字只适合作为宽阅读列的实验范围，不能成为窄屏或普通 Dialog 的最低行长。不要为凑字数扩大 Dialog、缩小字体或强加最小宽度。现有[编辑布局](EDITORIAL_LAYOUT.md)的16px/28px与最大38em属于另一场景，两个上限都不是通用偏好。

## 阅读位置与内容身份

静态排版不等于可调阅读器。当前对象展台只在存活宿主内按对象和页签保留像素位置，没有跨刷新持久化，也没有按内容修订、原文/摘要/译文恢复的公共 API。

- 同一内容、同一布局的普通关闭重开，实测恢复700px；整页重载为0。这是宿主内存状态的边界，不是持久存储承诺。
- 同一段落从16px改为18px后，复用旧1276px位置从第12段落到第10段；按稳定段落id重新定位才回到第12段。两段重复文字分别具有独立id，不能靠文本相等判断身份。该反例说明旧像素坐标不能证明语义位置连续，不代表本配方已经实现锚点恢复系统。
- 若另一个已授权产品需要可调排版或持久位置，宿主必须先区分对象、内容修订、呈现版本与段落身份，说明不匹配时的回退。等待目标内容和布局就绪、取消迟到恢复、权限重新校验以及焦点可见性属于该功能自身契约；本次不新增或承诺这些功能。
- [#61 已有增量](https://github.com/linhay/rhine-design/issues/61#issuecomment-6571804205)的反向页签焦点和失败重试位置缺陷仍独立记录，不以排版研究通过宣称修复。该基线复验：正文tab可被恢复滚动带到屏外；错误占位稳定后重试回到0，而立即重试可能恢复700。两条路径分别保留，不能以快速重试成功消除稳定占位的反例。

## 验证与排除范围

固定包530文件逐字源码＝tarball＝新安装；SHA256 `e5f53a43da51ce6c450107efcbcbfbc740226dd3cef54a3f36bfd463038fa76b`。主题与对象阅读定向19测试、类型与生产构建通过。独立合成宿主仅使用公开入口与宿主CSS，没有修改已安装包。

- 22个文章/普通Dialog场景：320/400/520/880宽、400/520/880的CSS zoom 2、320/880文本间距覆盖、400/880的18px正文。核对实际行片段、全文保留、英文/代码/长链接、重复段落身份、末段可达、局部表格/代码末端和预留图片加载后位置。界面文字仍14px。另4个页面/Dialog场景分别覆盖系统减少动态与手动减少动态，Dialog实际动画时长为0s，阅读与末段到达通过。
- 文本间距覆盖同时采用行高1.5、段后距2em、字距0.12em、词距0.16em。这是[SC 1.4.12](https://www.w3.org/WAI/WCAG22/Understanding/text-spacing.html)的适应性检查，不是建议默认使用这些值，也不要求新增字号设置面板。
- 普通正文320 CSS px宽度另验；CSS zoom与窄视口均不冒充原生浏览器400%缩放。必要二维布局的边界见[SC 1.4.10](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)。[SC 1.4.8](https://www.w3.org/WAI/WCAG22/Understanding/visual-presentation.html)的CJK行长与可调视觉机制属于AAA，不改写为AA默认字号要求。
- 正常/强制不换行/隐藏裁切三项对照检出对应异常；语言标记不删文，预留图像加载后的末段位移小于1px。局部滚动末端检查含程序化滚动，不据此宣称完整纯键盘横滚路径。
- **排除本轮功能**：需要真人判断的字体审美、舒适度/速度结论和依赖人工的实际读屏验收；不交给用户补验。可调字体控制、跨版本语义位置恢复、第三方解析器和真实服务没有当前独立需求，不为研究新增实现。历史失败与未验证项保留，不记为PASS。

本轮是配方与研究结论的文档交付；研究宿主不冒充正式产品或新基础组件，未发布npm、未升级消费项目、未修改UIKit。
